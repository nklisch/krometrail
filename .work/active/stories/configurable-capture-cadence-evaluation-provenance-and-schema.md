# Bind evaluation claims to the requested capture stride identity

## Checkpoint

Record the request-bound stride in the existing evaluation capture identity and preserve the
single digest path from manifest evidence to accepted claims/results. Regenerate the existing
canonical sample/schema only as implementation output; this design checkpoint makes no generated
artifact change.

## Exact implementation

**Files**:

- `crates/temporal-evaluation/src/manifest.rs`
- `crates/temporal-evaluation/tests/manifest.rs`
- `crates/temporal-evaluation/tests/live_qualification.rs`
- `src/app/live_evaluation/report.rs`
- `src/app/live_evaluation.rs`
- `src/app/live_evaluation/capture.rs`
- `docs/evidence/temporal-evaluation/v1/sample-manifest.json`
- `docs/evidence/temporal-evaluation/v1/run-manifest.schema.json`

Add `every_nth_frame: u8` to the existing `CaptureConfigIdentity` and validate it as 1..=60 in
the independent evaluation crate. Use 1 in `RunManifest::sample` and the report contract seed.
After a successful live browser connection, project `BrowserStatus.every_nth_frame` into
`KrometrailIdentity.capture_config`; an unavailable/no-session run remains an explicit non-passing
manifest and may retain the contract default because no session value was observed.

Do not add cadence to `AcceptedClaim`, `TrialScore`, or `EvaluationResultRecord`. Their existing
`evidence_ids` and `run_manifest_input_digest` already bind accepted claims to the one manifest
identity. Tests must show that changing only the requested stride changes the canonical manifest
and input digest, while retained evidence and claim validation continue to work.

Regenerate the checked-in evaluation contracts using the existing generator after implementation:

```text
cargo run -p temporal-evaluation --bin generate-run-manifest -- \
  docs/evidence/temporal-evaluation/v1/sample-manifest.json \
  docs/evidence/temporal-evaluation/v1/run-manifest.schema.json
```

The manifest test remains the authority that generated bytes match `run_manifest_schema()` and
`sample_manifest()` exactly. No unrelated documentation or generated artifact is touched.

## Acceptance evidence

- [x] Manifest identity accepts exactly 1..=60, rejects 0/61, serializes the requested value, and
      the generated schema advertises the same bound.
- [x] Live qualification report records the request-bound status value rather than a global or
      inferred cadence value.
- [x] Changing only stride changes manifest and input digests; accepted claims remain bound to
      retained evidence through the containing manifest identity, with no per-claim duplicate.
- [x] Existing sample/schema byte-equality tests pass after regeneration through the existing
      binary; no legacy reader or compatibility migration is added.
- [x] Requested stride remains provenance only: no FPS promise, ordinal-gap inference, or ordinary
      queue/persistence/visibility gap reclassification is introduced.

## Implementation notes

- Added the independent manifest scalar and range-backed generated schema metadata; the contract
  sample and unavailable/no-session report seed use `1`.
- Successful live session status is retained once and its `BrowserStatus.every_nth_frame` value is
  projected into `KrometrailIdentity.capture_config`. Failure paths keep the seed and remain
  explicitly non-passing.
- Added boundary/schema tests and retained-claim digest coverage. Changing only the identity from
  stride `1` to `60` changes both canonical and input digests while the retained claim/evidence
  validation remains unchanged. No cadence field was added to claims, scores, or result records.
- Regenerated only `sample-manifest.json` and `run-manifest.schema.json` through
  `generate-run-manifest`; updated the existing manifest artifact digest assertions.
- Verification passed under Rust 1.85: format, default workspace check/test/clippy, and all
  `qualification-support` check/test/clippy variants with live Chrome opt-ins unset.
