# Default explicit visual tools to one image

Materialize operation-sensitive image defaults, make artifact and filmstrip image requests effective, exclude structural web-area roots from generic actionability, publish bounded current semantic outcomes in live observations, and update foundation and agent guidance.

## Implementation notes

- `ResponseRequest.inline_images` is now an optional override. The MCP registry materializes omitted values from operation purpose: screenshot, live observation, temporal bundle, source-frame fetch, artifact generation, and region filmstrip routes default on; routine routes default off. Explicit booleans always win.
- Artifact and filmstrip response mapping now asynchronously reads the selected primary artifact through the existing progressive evidence boundary. Identity, scope, media type, encoded length, output hash, dimensions, deadline, cancellation, and the existing 8 MiB read limit are preserved. A missing read degrades the structured/resource response; cancellation remains terminal.
- AX decoding prevents `RootWebArea`, `WebArea`, and `document` nodes from becoming actionable through generic focusable/editable/clickable signals while retaining real role-based controls.
- Automatic live observations publish at most eight current semantic outcomes within a 4 KiB JSON budget. Alerts, dialogs, and status roles precede named text in canonical snapshot order; the projection does not claim a state transition.
- Foundation docs and the Krometrail skill now teach purpose-sensitive image defaults, explicit suppression, direct inspection of returned images, current semantic outcomes, chronological browser events, and range-handle drill-down. `docs/public/llms-full.txt` was regenerated by `bun run docs:build`.
- Queue inspection deviation: `.work/bin/work-view` is a Linux x86 executable and cannot run on this macOS host, so item/dependency state was inspected directly from the tracked markdown substrate.
